# Architecture

- Load order (`init.lua`): `settings` → `keymaps` (sets `<space>` as leader) → `autogroups` → lazy.nvim bootstrap → `require("lazy").setup("plugins")`.
- Plugin specs: one file per plugin in `lua/plugins/`, each returning a lazy.nvim spec table. `lsp.lua`, `dap.lua`, and `colorscheme.lua` return multi-plugin lists.
- LSP: mason + mason-lspconfig **v2** in `lua/plugins/lsp.lua`. Server configs are declared with `vim.lsp.config()` (shared `on_attach`/capabilities via `vim.lsp.config("*", ...)`; a server-specific `on_attach` *replaces* the `"*"` one and must chain it). `automatic_enable` starts every mason-installed server that has an lspconfig mapping — not just the `servers` list — so broken ones go in its `exclude` (currently `snyk_ls`, `stylua`). The v1 `handlers` option no longer exists.
- Treesitter: nvim-treesitter **main branch** (the rewrite — there is no `nvim-treesitter.configs` module). Highlighting and indent attach per buffer via a `FileType` autocmd in `lua/plugins/treesitter.lua` calling `vim.treesitter.start()`; parsers are compiled by the tree-sitter CLI (`brew install tree-sitter-cli`) into `stdpath("data")/site`. Commands: `:TSInstall`, `:TSUpdate`, `:TSUninstall`, `:TSLog`. Incremental selection (`<C-space>`/`<bs>`) is a local shim in the same file (upstream dropped the module).
- Keybindings live in three tiers: global (`lua/keymaps.lua`), per-plugin (inside each spec's `config`/`keys`), and conditional (autocmds in `lua/autogroups/init.lua` — Gradle-project maps, Kotlin/Java test-file jump via `lua/autogroups/kotlin.lua`). Convention: every mapping gets a `desc`; `:Telescope keymaps` is the discovery mechanism (which-key is installed but unconfigured).

# Gotchas

- The `@Disabled` first-line marker read by `lua/plugins.lua` is a **no-op**: lazy's `{ import = "plugins" }` loads every `lua/plugins/*.lua` on its own. Disable a plugin with `enabled = false` in its spec instead.
- Ignore `lua/lazy.nvim/` — a vendored upstream clone of lazy.nvim, not on the runtimepath; exclude it from greps and searches.
- Dead files, do not take as reference: `lua/lsp.lua.bak`, `lua/lsp/java.lua` (orphaned, never required), `lua/plugins/rust-tools.lua` and `lua/plugins/null-ls.lua` (empty stubs).
- Never hand-edit `lazy-lock.json`; it is regenerated by `:Lazy sync`/`:Lazy update`. Prefer `:Lazy update <plugin>` for targeted updates — a full `:Lazy sync` bumps every unpinned plugin at once and can pull in breaking API changes across the fleet.
- telescope.nvim tracks `master` deliberately: the `0.1.x` branch is frozen and incompatible with the nvim-treesitter main branch.

# Commands

- `nvim --headless "+Lazy! sync" +qa` — install/update plugins per specs (blocking).
- `nvim --headless "+TSUpdate" +qa` — update treesitter parsers (requires the tree-sitter CLI).
- `:checkhealth nvim-treesitter`, `:checkhealth lazy`, `:checkhealth mason` — diagnose.
- Smoke test after changes: open a file of the affected filetype and check `:messages` for errors.
