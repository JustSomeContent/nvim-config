# Architecture

- Load order (`init.lua`): `settings` → `keymaps` (sets `<space>` as leader) → `autogroups` → lazy.nvim bootstrap → `require("lazy").setup("plugins")`.
- Plugin specs: one file per plugin in `lua/plugins/`, each returning a lazy.nvim spec table. `lsp.lua`, `dap.lua`, and `colorscheme.lua` return multi-plugin lists.
- LSP: mason + mason-lspconfig **v2** in `lua/plugins/lsp.lua`. Server configs are declared with `vim.lsp.config()` (shared `on_attach`/capabilities via `vim.lsp.config("*", ...)`; a server-specific `on_attach` *replaces* the `"*"` one and must chain it). `automatic_enable` starts every mason-installed server that has an lspconfig mapping — not just the `servers` list — so broken ones go in its `exclude` (currently `snyk_ls`, `stylua`). The v1 `handlers` option no longer exists. Pyright resolves the project interpreter in `before_init`: an activated `VIRTUAL_ENV` wins, else the nearest `.venv`/`venv` searching upward from the LSP root (covers `uv`-managed projects and workspaces); after creating a venv mid-session, restart with `<leader>rs`.
- Treesitter: nvim-treesitter **main branch** (the rewrite — there is no `nvim-treesitter.configs` module). Highlighting and indent attach per buffer via a `FileType` autocmd in `lua/plugins/treesitter.lua` calling `vim.treesitter.start()`; parsers are compiled by the tree-sitter CLI (`brew install tree-sitter-cli`) into `stdpath("data")/site`. Commands: `:TSInstall`, `:TSUpdate`, `:TSUninstall`, `:TSLog`. Incremental selection (`<C-space>`/`<bs>`) is a local shim in the same file (upstream dropped the module).
- Keybindings live in three tiers: global (`lua/keymaps.lua`), per-plugin (inside each spec's `config`/`keys`), and conditional (autocmds in `lua/autogroups/init.lua` — Gradle-project maps, and `<leader>jt` test-file jump via `lua/autogroups/kotlin.lua` and `lua/autogroups/elixir.lua`). Convention: every mapping gets a `desc`, and each leader prefix has a which-key group label in `lua/plugins/which-key.lua`; `:Telescope keymaps` and the which-key popup are the discovery mechanisms.
- Claude Code: claudecode.nvim (`lua/plugins/claudecode.lua`) runs the VS Code-extension IDE protocol in-editor (WebSocket server + `~/.claude/ide/<port>.lock`) against the local `claude` CLI — subscription auth, no API key. Terminal `provider = "native"`: `<leader>ac` toggles (and `<leader>af` focuses) a full-height vertical split on the right (`<leader>ar`/`<leader>aC` open it with `--resume`/`--continue`) whose env the plugin pins to this instance's server via `CLAUDE_CODE_SSE_PORT` — don't use `claude --ide`, which only auto-connects when exactly one IDE lock file exists (VS Code windows also write them). Leave the claude pane with stock `<C-\><C-n>`; it must not be a toggleterm terminal, because toggleterm maps `<C-\>` in terminal mode inside its own buffers and would swallow it (`<C-\>` stays the toggleterm float's key). `<leader>wm` (vim-maximizer) zooms/restores any split, the claude pane included. Selection/context sharing and native diffs (`<leader>aa`/`<leader>ad`) come from the plugin; a claude launched anywhere else must pick "Neovim" via `/ide`. If sends time out, the CLI isn't attached to this instance's server.
- Formatting: conform.nvim (`lua/plugins/formatting.lua`) formats on save, but only filetypes with an explicit formatter entry (elixir/heex/eex via `mix format`, lua via stylua, web via prettierd, python via ruff — organize-imports then format, replacing isort+black; conform prefers `.venv/bin/ruff` over the mason install) — no LSP fallback on save.
- The repo is under git. Commit after every meaningful change with a message describing the why.

# Gotchas

- Every file in `lua/plugins/` is loaded by lazy's `{ import = "plugins" }`. Disable a plugin with `enabled = false` in its spec — do not invent marker comments.
- Never hand-edit `lazy-lock.json`; it is regenerated by `:Lazy sync`/`:Lazy update`. Prefer `:Lazy update <plugin>` for targeted updates — a full `:Lazy sync` bumps every unpinned plugin at once and can pull in breaking API changes across the fleet.
- telescope.nvim tracks `master` deliberately: the `0.1.x` branch is frozen and incompatible with the nvim-treesitter main branch.

# Commands

- `nvim --headless "+Lazy! sync" +qa` — install/update plugins per specs (blocking).
- `nvim --headless "+TSUpdate" +qa` — update treesitter parsers (requires the tree-sitter CLI).
- `:checkhealth nvim-treesitter`, `:checkhealth lazy`, `:checkhealth mason` — diagnose.
- Smoke test after changes: open a file of the affected filetype and check `:messages` for errors.
